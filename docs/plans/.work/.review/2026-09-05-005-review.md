# Work Report — 2026-09-05-005-review (2026-09-05-007)

## What the run was for

A generation run logged a structured tool failure:

```json
{ "code": "not_found", "message": "no directory at \"docs/tasks\" inside the output directory." }
```

The sandbox produced that answer correctly. `agent/src/skill-prompts.ts` inlines
`.agents/skills/work/SKILL.md` **verbatim** as the executor's binding procedure, and that body orders a
Pre-Flight Check over `docs/tasks/` with `mkdir -p` self-healing, names
`docs/tasks/<plan-id>/index.md` as one of the call's durable outputs, and opens with a `git` branch step.
The executor's tools reach only the generated app's output directory (`agent/src/tools/fs.ts`) and
`run_command` only allow-listed npm scripts, while `docs` is excluded from the scaffold by
`DEFAULT_EXCLUDE` (`agent/src/scaffold.ts:33`). Every one of those instructions was therefore guaranteed
to end in a refusal the model cannot act on. The weaker local rule in `agent/src/prompts/generator.ts`
("do not create any planning artifact under `docs/`") lost the argument with the skill body below it.

Fix, at the prompt boundary only: the injected block now states which sections the harness performs
around the call and why their paths are unreachable, and no longer claims a `docs/` path as an output of
the call.

## Learnings to Capture (hand to `/learn`)

1. **Verbatim skill injection needs its impossible sections voided by name** — `type: gotcha`,
   `domain: agent-runtime`, source `2026-09-05-007-T01` / green gate. Injecting an
   interactive, repository-resident skill into a sandboxed single LLM call does not just add noise: the
   model *obeys* the skill and spends iterations on guaranteed refusals (`list_files("docs/tasks")` →
   `not_found`, `read_file("../docs/…")` → `path_escape`, `run_command("git checkout -b …")` → off the
   npm allow-list). A prose "don't do that" rule elsewhere in the prompt is not enough — it has to name
   the sections being voided and state that the refusal is correct rather than an obstacle.
2. **One rule, one author: assert prompt invariants by occurrence count** — `type: confirmed-pattern`,
   `domain: testing`, source `2026-09-05-007-T02` / red gate. When a rule is restated in two modules,
   `toContain` cannot detect the duplication; `expect(text.match(/sentinel/g)).toHaveLength(1)` turns the
   duplication itself into the failing assertion.
3. **A doomed branch base beats a rule-following one** — `type: forced-decision`, `domain: workflow`,
   source Triage Step 2d. Autopilot says "create the work branch from the default branch"; when the
   files under change exist only on an unmerged `work/*` branch, following it produces a branch that
   cannot succeed. Deviate, record `work-branch-base` truthfully, and surface the merge coupling.
4. **Refuted assumption (partial)** — `docs/learn/pattern/test-config-isolation-behaviorally-not-regex.md`
   advises proving behaviour with real tooling rather than matching text. For prompt assembly the rendered
   text *is* the behaviour, so the pattern does not apply; the durable lesson is narrower — assert on
   short stable sentinels, never whole sentences, or rewording reads as regression.
