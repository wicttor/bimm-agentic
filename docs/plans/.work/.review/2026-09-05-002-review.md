## Learnings to Capture (for `/learn`)

1. **Allow-lists over command strings need normalize-before-match, not match-over-shell** (decision, agent-runtime, T05/Green) — accept only `typecheck` / `npm run typecheck` token shapes so chains, args, and metacharacters cannot survive into the runner; the membership check runs before any exec seam exists.
2. **Not every npm script is loop-safe: exclude non-terminating entries** (forced decision, agent-runtime, T05/Green) — the allow-list is `typecheck/test/build` only; `dev`, `preview`, `test:watch` exist in the boilerplate but would hang the tool loop; asserted explicitly in tests.
3. **Tool-error taxonomy separates sandbox rejections from command outcomes** (decision, agent-runtime, T05/Green) — non-zero exit is `execution_failed` with output in `details` (information for the model), while path/cap/allow-list violations are distinct `path_escape`/`file_too_large`/`command_not_allowed` codes; the loop branches on code, not prose.
4. **Sandbox containment should reject before existence checks** (pattern, security/testing, T05/Green) — lexical `resolve` + `relative` prefix test run before any `existsSync`, so a rejected read leaks neither content nor existence; assert the no-leak in the test itself.
5. **Barrel re-exports create handler↔registry value cycles** (gotcha, typescript, T05/Review) — handlers import types (erased) from the registry barrel while it re-exports their constants; hoisting shared runtime helpers into the barrel would close a real cycle, so 4-line duplication can beat a circular import.
