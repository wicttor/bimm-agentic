## Learnings to Capture (Step 5 → `/learn`)

1. **gotcha — `machine-readable-validation-output`** (typescript/testing) · source: T06 · Green.
   The concrete shapes the parsers key on, measured not assumed: `tsc --pretty false` emits
   `src/x.ts(2,9): error TS6133: msg` plus indented continuation lines and an npm banner;
   `arr[i]` under `noUncheckedIndexedAccess` surfaces as **TS2322** (`Type 'string | undefined' is
   not assignable to type 'string'`) — not a dedicated indexed-access code — and
   **TS6133 covers both `noUnusedLocals` and `noUnusedParameters`**, so a code list cannot tell the
   two flags apart. Closes the gap the task file named.
2. **gotcha — `vitest-json-report-absolute-suite-names-and-stacked-failures`** (testing) · source: T06 · Red.
   `vitest run --reporter=json` prints its report to stdout **after** npm's `> pkg@ver test` banner
   (locate the object by outermost braces, never `JSON.parse(stdout)`); `testResults[].name` is an
   **absolute** path where tsc's are relative; a suite that fails to *load* reports
   `status: "failed"` with an **empty `assertionResults`** and the reason on `suite.message`;
   assertion line numbers exist only inside `failureMessages[]` stack frames, where the runner's own
   node_modules frames must be filtered out; and no `VITEST_REPORTER` environment variable exists, so
   the reporter can only be chosen on the command line.
3. **forced-decision — `machine-readable-flags-belong-downstream-of-the-allow-list`**
   (agent-runtime) · source: T06 · Prepare/Red.
   `run_command` normalizes to a bare npm script name and rejects arguments **by design**, so a
   validator cannot ask for `--pretty false`/`--reporter=json` through it. Resolution: run the
   allow-listed script names through `executeTool`, and append the flags in the injected
   `ScriptRunner` (`defaultRunScript`), strictly after the allow-list check — the sandbox still owns
   what executes (proven by an `allowedScripts: ["build"]` case that reaches the runner zero times),
   and a rejection surfaces as the result's `error`, never as a clean report.
4. **confirmed-pattern — `a-clean-baseline-assertion-must-run-the-real-toolchain`**
   (testing) · source: T06 · Red.
   Probing "the untouched scaffold is clean" against a real `tsc` + `vitest` run (scaffold into a
   temp dir, symlink the repo's `node_modules` — no `npm install`, no network) found a cross-task
   bug that every fixture-based test would have hidden: the scaffolder's copy could not typecheck at
   all. Keep injected-runner fixtures for per-case precision and add a small number of real probes
   where the AC's claim is about real tool output.
5. **gotcha — `parse-silence-is-not-success`** (agent-runtime) · source: T06 · Refactor.
   For a validation seam feeding a repair loop, an empty error list is only meaningful if the tools
   actually ran and were understood. Four non-obvious cases had to be made visible as errors rather
   than zero-counts: missing `node_modules`, a tool that exits non-zero with nothing parseable, a
   vitest report with `numTotalTests: 0`, and a report whose `numFailedTests` exceeds what the JSON
   maps. Silent zero → loop terminates on a broken app.
