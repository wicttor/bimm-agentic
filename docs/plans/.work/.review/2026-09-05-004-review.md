## Learnings to Capture (Step 5 → `/learn`)

1. **gotcha — `strip-only-node-rejects-what-tsc-and-esbuild-accept`** (typescript/node) · source:
   T07 · Refactor.
   A constructor parameter property compiles clean under `agent:typecheck` and passes every vitest
   test (esbuild transpiles it away), while `node agent/src/index.ts` under strip-only type removal
   fails to *parse* the module at load time. The repo's existing real-CLI spawn test cannot see it,
   because `index.ts` only reaches `config.ts`. Prevention: any module that will be loaded by the
   spawned runtime gets a test that spawns `node` and `await import`s it; the probe is cheap (~80ms)
   and it is the only gate for this class. Proven by re-inserting the defect: `tsc` clean, **54 of 55**
   tests passing, only the probe red.
2. **pattern — `derive-rules-from-fixture-geometry`** (prompt-engineering/agent-runtime) · source:
   T07 · Green.
   The responsive breakpoint table has no prose source in this project — it is encoded in the seed
   fixtures' image dimensions (`640x360`, `1023x576`, `1440x810`). Tiers are derived by collecting
   every dimensioned image URL, sorting by width, and giving each tier its own width as its ceiling
   and the tier below plus one pixel as its floor, which reproduces `≤640 / 641–1023 / ≥1024`
   exactly, with no slot name and no pixel constant in the code. Generalizes: a fixture naming its
   slots `thumb`/`hero` derives correctly. This is how a rule can be *derived* when no file states it
   as a rule.
3. **pattern — `prohibition-test-pairs-with-drift-test`** (testing) · source: T07 · AC.
   "Rules are derived, not duplicated as prose" needs two complementary tests, and each is blind to
   what the other catches: the drift test edits the source file and asserts the rendered prompt
   follows (catches a rule that ignores its file), and the prohibition test reads the production
   module's own text and asserts no rule payload appears in it (catches a hardcoded copy sitting
   beside a derivation that also works). Either alone passes on a module containing both a working
   derivation and a dead hardcoded string.
4. **gotcha — `never-run-two-mutating-harnesses-in-parallel`** (testing/verification) · source:
   T07 · Review.
   Mutation harnesses mutate tracked files in place and restore from an in-memory copy. Two in
   parallel produce results that look like evidence and are not: one harness aborts on a match count
   it can explain only by the sibling's edit, and the other's failure counts silently include the
   sibling's defect. Same failure family as the T04/T05 racing-`git commit` and no-op-mutation
   incidents; the general rule is that mutation testing is a serial resource.
5. **gotcha — `attached-file-content-is-not-the-file`** (workflow) · source: T07 · Step 0.
   The copy of the task file supplied with the request differed from the file on disk: five extra
   sections, and an Open Q naming two files from another project. Acting on the attachment would have
   invented requirements; acting on the disk file alone would have missed that the brief was wrong
   (and that the user may be looking at the wrong text). Prevention: when an attached artifact drives
   scope, read the file it claims to be and surface the divergence before writing production code.
