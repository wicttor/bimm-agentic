## Learnings to Capture (hand to `/learn`)

1. **`**/*` inside a TS block comment silently closes the comment** — gotcha · testing/typescript ·
   source: T01 / Red. A JSDoc line containing a glob like `agent/**/*.test.ts` contains `*/`, which
   terminates the block comment early and yields a baffling esbuild "Unexpected *" parse error. Use
   `//` line comments for text containing globs, or don't embed `*/` in a `/** ... */`.
2. **Don't extend the app tsconfig from a node sub-project** — decision · tooling/build-isolation ·
   source: T01 / Green. Extending the root would leak DOM libs, the React `jsx` transform, and the
   `@/*` path alias into `agent/`. A standalone `agent/tsconfig.json` with `types: ["node"]` and no
   DOM lib keeps the two compilation units honest.
3. **Test config isolation behaviourally, not by regex-on-config** — pattern · testing ·
   source: T01 / Green. The wiring test asserts real outcomes: `vitest list` collection excludes
   `agent/`, `globalThis.window/document` are undefined in the node run, and a throwaway type-error
   probe file makes `agent:typecheck` fail while `typecheck` passes. Guard against vacuous
   "config contains a string" tests.
4. **A node-env TS sub-project needs `@types/node`** — decision · typescript · source: T01 / Green.
   With `types: ["node"]` and `lib: ["ES2022"]` (no DOM), `tsc` cannot resolve `node:*` imports
   without `@types/node`; needed even though the runtime doesn't use it.
