## Step 5 — Learnings to Capture (run `/learn`)

Five code/test candidates below, plus a sixth from the branch anomaly at the end of
this report. Work does not write `docs/learn/` itself.

1. **pattern — provider-agnostic function calling** _(domain `llm-integration`, source T03/Green)_
   **This closes the first half of the plan's `llm-integration` learning gap**, which the plan says
   to capture "after U2/U8" — U2 (adapters) is now done, **U8 (token-budget trimming) is not**, so
   `/learn` should record the adapter divergence now and revisit for budgeting. The five axes where
   Anthropic and OpenAI genuinely diverge: system placement (top-level field vs leading
   `role:"system"` message), schema key (`input_schema` vs `function.parameters`), tool-args type
   (object vs JSON **string**), usage field names (`input_tokens`/`cache_*` vs
   `prompt_tokens`/`completion_tokens`/`prompt_tokens_details.cached_tokens` — OpenAI has no
   cache-write counter at all), and stop vocabulary (`end_turn`/`max_tokens`/`tool_use` vs
   `stop`/`length`/`tool_calls`). Where they _don't_ diverge: retry policy and error classification —
   both are plain HTTP status codes, so the transport and backoff can (and does) live in one shared
   function.
2. **pattern — sentinel-stub Red keeps the Red gate honest** _(domain testing, source T03/Red)_
   Create the modules as type-correct stubs returning an empty-but-well-shaped result. The test then
   fails on **AC assertions** (18/18 here) instead of on an import error or a
   "NotImplementedError" throw, both of which check the wrong thing. Needed because `agent/tests/**`
   is typechecked: the stubs must compile for Red to be assertion-level.
3. **gotcha — a second `stubFetch` replaces the first** _(domain testing, source T03/Green)_
   Re-installing `globalThis.fetch` per provider inside one test silently serves the second payload
   to the first call — a confusing cross-adapter failure. Use **one** stub that dispatches on request
   URL when a test exercises several endpoints.
4. **gotcha — scripted-fake exhaustion reads like an adapter bug** _(domain testing,
   source T03/Green)_ A fake that fails loudly when replies run out produced a genuine-looking
   failure whose real cause was a test scripting 1 reply for 2 calls. Loud exhaustion is the right
   design (T10's loop tests depend on it); match reply count to call count.
5. **gotcha — a mutation check that silently no-ops** _(domain testing/review, source T03/Review)_
   See the mutation table above: assert the source edit actually applied before treating a green run
   as evidence about test strength.

**Learning gaps carried forward:** `llm-integration` (half-closed by this task — token budgeting
still owed after U8); `agent-runtime` (U9/U10) and `tooling` (U5) unchanged.

## Branch Coherence Anomaly (orchestrator gate #5)

The run was configured for `work/cli-agentic-code-generator` and Triage verified it (`already-on`,
clean tree). **Mid-run, an external process changed the branch state** — the reflog records:

```
HEAD@{4}: checkout: moving from work/cli-agentic-code-generator to main
HEAD@{3}: merge e41a38e...            # work-branch tip merged into main
HEAD@{2}: commit: Add provider-agnostic LLM adapter (T03)
```

Consequences and resolution:

1. The three T03 commits landed on **`main`**, not the work branch → gate #5 mismatch.
2. Before it could be corrected, the same external automation **pushed `main` to `origin`**
   (`origin/main@{0}: update by push` → `585be34`), so the commits became published history. This is
   also how T01/T02 reached `main`, so it matches the repository's existing session-end convention.
3. User decision (two explicit prompts, not silent): first to move the work to the work branch, then
   — after learning the commits were already pushed — to **accept it and stop rewriting**. The
   alternative (force-pushing `main` back) would have rewritten published history and been undone by
   the automation at the next session boundary.

**Final state:** `main` = `origin/main` = `work/cli-agentic-code-generator` = `585be34` (no
divergence, no rewrite); the work branch is checked out for the next task. Nothing about T03's code,
tests, or task status was affected — only which branch name the commits were born on.

> **Learning candidate #6 (workflow):** an external session-end automation in this repository checks
> out `main`, merges, and pushes while a Work run is in flight, and it pushes whatever commits exist —
> including mid-run work. A Work run should re-verify `git branch --show-current` immediately before
> each commit rather than trusting the Triage reading, because a branch created and verified at
> Triage is not guaranteed to still be checked out at Execute.
