## Learnings Surfaced (for /learn)

1. **pattern — provider-agnostic function calling** (the plan's learning gap, now satisfiable): the
   two providers disagree on _every_ axis the loop cares about — system placement (top-level vs
   message), schema key (`input_schema` vs `function.parameters`), tool-args type (object vs
   JSON string), usage field names, stop vocabulary. Normalizing all five behind one interface and
   testing each adapter against a stubbed `fetch` confines drift to a single red unit test.
2. **pattern — sentinel-stub Red to keep the Red gate assertion-level:** creating the modules as
   type-correct stubs that return an empty result makes Red fail on AC assertions; a Red that fails
   on "not implemented" throws or import errors checks the wrong thing.
3. **gotcha — a second `stubFetch` replaces the first:** queuing per-test stubs by re-installing
   `globalThis.fetch` silently serves the wrong payload to the earlier call; dispatch one stub on
   request URL when a test exercises multiple endpoints.
4. **gotcha — shared `fake` exhaustion errors look like adapter bugs:** a scripted provider that
   fails loudly on exhaustion surfaces as a confusing error when a test scripts too few replies;
   match reply count to call count (or the loud failure is the point).
