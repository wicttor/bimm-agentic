# Scoped Context

## Problem

The repo currently holds only the provided React + TypeScript **boilerplate** for a
Car Inventory Manager. Per `README.md`, the graded deliverable is **not** the app — it is
an **agentic workflow**: a CLI tool that reads a natural-language spec, decomposes it into
ordered tasks, generates application code into the boilerplate with file-level dependency
awareness, self-validates by running the real test suite and type-checker, and iterates on
failures. No agent code exists in the repository yet (`src/App.tsx` is still the placeholder
shell; `src/components/Example.tsx` is reference-only).

## Intended Behavior

Running the CLI against a spec file produces a **copy** of the boilerplate populated with
generated components/hooks/tests, such that:

```bash
cd generated-app && npm install && npm run dev     # app renders the spec'd features
npm run test && npm run typecheck                  # pass, after >=1 validation/retry cycle
```

The agent's plan, per-file generations, validation output, and repair attempts are recorded
as traceable artifacts so a reviewer can see the loop rather than infer it.

## Success Criteria

1. **Runnable output** — the generated app passes `npm run typecheck` and `npm run test`, and
   implements the six required behaviors from `README.md`: Apollo/MSW `GetCars` list,
   responsive image selection (<=640 mobile / 641-1023 tablet / >=1024 desktop), MUI cards,
   AddCar mutation form, model search + year/make sorting, and a `useCars()` hook.
2. **Real agentic loop, demonstrated** — spec -> dependency-ordered task decomposition ->
   file-by-file generation -> validation -> **at least one** error-driven repair iteration,
   each step visible in artifacts and unit-testable in isolation.
3. **Generalizes + is submittable** — the agent still produces a working app when the spec is
   slightly modified, and the submission ships with `.env.example`, a sample spec file,
   a sample output directory, and a README documenting architecture decisions and cost.
